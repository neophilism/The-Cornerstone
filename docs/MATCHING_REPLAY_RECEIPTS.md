# Reproducible synthetic replay receipts (CS-20 partial contribution)

`replayFailedMatches(round, events)` now returns `verifiedEvents` alongside the existing `steps`, `matches`, and `declinedPairs`. Each entry contains the accepted one-based sequence, exact failed pair, willing applicant IDs, and **computed** before/after allocation snapshots. No field is a direct alias of the caller's mutable transcript; all identities and arrays are freshly copied from the validated event and the actual matching calculation. Permuted, otherwise valid allocation evidence is serialized in the algorithm's deterministic ordering.

This closes a local evidence-recovery gap: `steps` alone omitted the willingness set and predecessor allocation, so it could not serve as the input transcript for another replay. Given the **same independently authenticated round**, a consumer can now call `replayFailedMatches(round, result.verifiedEvents)` and compare the complete deterministic result. On malformed or contradictory source evidence, the function still fails closed and produces no verified receipt.

This is a replayable **synthetic computation record**, not a cryptographic signature, independently witnessed transcript, storage durability guarantee, immutable JavaScript object, proof of legal consent, or external acceptance. Anyone who controls both the round and its transcript can forge a self-consistent calculation. Authenticating the original frozen round, witnessing each event, signing or sealing source-bound receipts, independently holding ranking keys, and authorizing disclosure remain separate CS-20 requirements. Do not enable real sealed rankings or protected intake on this basis.

`tests/matching-replay-verified-events.test.ts` covers exact multi-step replay round trips, canonical ordering, maliciously mutated caller inputs, absence of references shared with other result fields, invalid allocation rejection and empty histories. Require complete application, actual PostgreSQL (where applicable), source and desktop/mobile browser checks against the exact eventual GitHub head before accepting this partial implementation.
