# Complete synthetic activity history

The authenticated inbox now has bounded keyset pages rather than silently stopping at 100 entries. `GET /notifications` accepts only an optional 1-100 limit and opaque cursor; the default is 50. Its response adds `nextCursor` and a count of all currently accessible unread entries, not merely unread items on the current page.

The server encrypts and authenticates the continuation boundary for the exact subject and realm. It preserves PostgreSQL timestamp microseconds and orders by descending creation instant and UUID. Cursors confer no permission: current row-level security, revoked grants and conflicts are checked again for every page and count. Supplied recipient identifiers, tampered or cross-account cursors and malformed limits are rejected. New entries require a refresh; pagination is not an immutable historical snapshot. A page and its unread count are computed in one SQL statement.

Marking an entry read returns only permitted identifiers and their authoritative read timestamps, plus the current unread total. The operation is repeatable without changing an existing read timestamp. The workspace updates loaded entries without losing its place, loads older entries, opens references through the existing current-access check, and discards late page/read responses after a session or refresh boundary. Reading activity never supplies legal service or acceptance. No new database migration or production integration is needed; migrations 001-015 are still required by the current runtime.

Verification: `tests/activity-pages.test.ts` checks wire limits and truthfulness. `tests/activity-pages.integration.ts` checks 207 rows, microsecond/UUID ties, authenticated cursor binding, outsider and conflict denial, authoritative read persistence and full counts on actual PostgreSQL. Owner-generated historical inbox fixtures are explicitly synthetic; worker delivery remains separately tested by `activity.integration.ts`. The browser journey checks older entries, preserved position after marking read, scoped record opening, mobile/desktop accessibility and overflow. CI and screenshot observations must be recorded only after they execute.
