# Synthetic replay checkpoint threat review — October 17, 2026

This document is a proposed CS-20 development boundary, not accepted code or an audit. A frozen-round signature can authenticate the inputs of a match but cannot authenticate subsequent negotiation events. A completed replay therefore needs a separately signed event transcript and independently anchored checkpoint ID, release ID and predecessor digest. The verification path must reject malformed transcript records, unbounded arrays, signer-key aliases, revoked trust roots, wrong source versions, invalid clocks and conflicting final allocations. Replaying a cryptographically valid history is distinct from proving the events occurred.

The repository's current `main` and all seven original source byte streams remain authoritative. Actual independent custody, append-only compare-and-swap to prevent forks, provider identity/revocation, legal authorization and production sealed-rankings activation are not implemented by a synthetic signing helper. This partial design must be tested against the real matching engine, negative permission paths and complete required application/source/metadata and desktop/mobile browser CI before a safe merge.
