# Version-bound synthetic matching replay commitments

This bounded **CS-20** contribution adds `hashVerifiedReplay(round, events, sourceCommitSha)` and `verifyVerifiedReplay(round, events, commitment, expectedSourceCommitSha)` to the pure matching package. The calculation first validates the frozen matching inputs and every claimed negotiation against independently recomputed allocations. It then computes a domain-separated SHA-256 checksum and returns the detached, verified replay alongside the checksum metadata. The verifier recomputes the checksum and rejects a contradictory transcript, changed source revision, malformed digest, accessors and revoked-proxy receipt metadata.

The verifier now requires an **independently supplied expected source commit SHA**. It rejects a fully self-consistent, rehashed receipt that substitutes a different source revision; the receipt cannot choose its own expected reference. The caller must obtain the expectation through a trusted release inventory or another authenticated channel. A caller that accepts an attacker-chosen expectation still has no source provenance.

The exact lowercase 40-character Git commit identifier supplied by the caller is included inside the checksum, alongside the `cornerstone-synthetic-replay-v1` domain. The commit identifier is **claimed metadata, not independently authenticated provenance**. A trusted future custodian must establish the code revision actually executed and bind its receipt to signed and retained evidence. This library does not do that.

Canonical JSON encodes, in order: domain, claimed source commit, algorithm, round identity, each applicant's identity, priority date, ordered choices, readiness, remediation and sorted constituent identities, each offer's identity, published version, sorted exclusive rights and eligibility, the ordered public tie draw, computed initial allocation, complete numbered verified events with failed pairs, sorted willingness identities and recomputed before/after allocations, and final allocation. Applicants, offers and logical sets are sorted by explicit UTF-16 string ordering; ranked choices, draw order and sequence retain their meaningful order. Allocations are ordered by offer and applicant. Changing offer terms, frozen ranking, algorithm, source revision, event evidence or final allocation either changes the digest or fails validation.

This is **only a deterministic integrity comparison**. Any adversary able to replace the input records and checksum can generate another self-consistent value. The checksum is not a digital signature, secure timestamp, independent escrow, custody service, witnessed draw, authorization receipt or proof of participant consent. Matching choices and full transcripts may be confidential: do not publish digest inputs or treat an unhashed identifier or low-entropy secret as private merely because it appears within a SHA-256 calculation. No private API, production intake, ranking release, compact delivery, official action or disbursement is enabled.

The new regression suite covers independently expected source revision checks, self-consistent receipt substitution rejection, repeatability, independent reference vectors, equivalent unordered-set permutations, ordered-draw and source/version binding, failed-event tampering, stale digest rejection, malformed and accessor-bearing receipts, independent returned evidence and empty histories. The final GitHub head must pass application, actual PostgreSQL, source/metadata and complete desktop/mobile browser gates before checked merge. This contribution does not complete CS-20 custody or external acceptance.
