# Frozen-round continuity for synthetic matching replay

Synthetic matching replay reports one named frozen round. An event array is untrusted data and its property-descriptor traps can mutate caller-owned objects. Before this change, replay validated the round through `match(round)` but subsequently consulted the original mutable round for applicant choices, offer eligibility, and the displayed `roundId`. A hostile event descriptor could change `round.id` after initial validation, yielding an apparently successful transcript mislabeled with the substituted round identity. Altering an applicant's choices after initial matching could also invalidate continuation unexpectedly.

`replayFailedMatches` now takes one detached structured clone of the provided round before reading any replay-event descriptors. Initial matching, every continuation, cardinality limits and reported round identity use that same snapshot. Non-cloneable rounds fail with typed `INVALID_ROUND` instead of leaking an unclassified clone exception. Existing ranking validation still runs on the detached round; caller-owned inputs are not modified by the implementation.

`tests/matching-replay-frozen-inputs.test.ts` covers descriptor-triggered mutations of round identity and applicant choices, a non-cloneable proxy round and normal/empty replay. The separate offline regression reproduces the identity-substitution defect on the predecessor before verifying the correction. This is defensive isolation of synthetic in-process data, **not** cryptographically authenticated source/version binding, independent custody, a sealed-choice protocol or institutional acceptance. The snapshot carries the ordinary copying cost of the supplied round; this slice does not set a provider or production quota.
