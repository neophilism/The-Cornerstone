# Synthetic state authority and immutable offer publication

This completes a bounded part of CS-19 using the existing state-authority and offer workflows, financial editor and commercial-menu editor. A state participant can prepare an authority packet, submit it to independent assigned supervision, prepare a complete offer under the exact verified authority, and disclose a frozen offer snapshot to signed-in simulation participants. The **Published offers** navigation provides participant inspection without private-record or evidence access. Withdrawal closes future choices while keeping the original publication and existing compact obligations intact.

Everything here is synthetic preparation. The receipt does not establish actual enactment, an appointment, legal authority, public notice or service, an Exchange, a signature, a payment, or certification. The existing production authority and ranking-provider gates remain separate. State legal findings and source references are reviewed assertions in this simulation.

The recorded final-rules date is an asserted synthetic source date, not proof of legal publication. Offer publication time comes from server acceptance; backdating the form cannot fabricate an earlier 90-day period. The snapshot records the exact earliest close instant, 90×24 hours after accepted publication (or final rules, if later). SQL uses UTC independently of the caller's database timezone, including DST changes. This date is preparation information and does not activate rankings.

The separate 60-day no-new-harm objection process, complete supervision decisions and appeals, actual notice acceptance, statutory completeness by the proper institution, appropriations, appointments, permits, external signatures and Exchange custody/results remain separate work. A synthetic supervisor verification is not a claim that the application's user holds an official statutory office.

## Usable path

1. A privileged simulation state participant creates an authority packet using the existing financial editor and public-reference fields, attaches and checks invented evidence, and submits it. The server records the originating actor, state institution and jurisdiction. A separate eligible supervisor must be routable before submission succeeds.
2. The assigned supervisor reviews the packet and records independent synthetic verification. The immutable authority revision includes the exact financial terms, dates, public references and a digest of the private packet/review basis. The database atomically reserves the positive percentage for that jurisdiction/Rate Act. Concurrent contradictory packets cannot both verify; mathematically equivalent fractions are accepted while each packet keeps its supplied representation.
3. The state prepares an offer using the existing rate/method and commercial-menu editors. It identifies the authority and supplies complete public readiness, obligations and protections. Submission freezes the complete draft and exact verified authority revision. Review, adverse finding and publication all recheck the current revision, validity period, withdrawal status, role, assignment, institution, jurisdiction and conflicts.
4. Publication requires intentional disclosure and written public findings separate from internal review reasons. The immutable catalogue projection includes the title, trade/district, listed public obligations, complete rate/method/menu, fixed maximum term, selected public authority references, source revision/digest and publication timing. It excludes private evidence IDs/bodies/descriptions, internal reasons and working analysis, history, raw data, proposing/reviewing personal IDs and private grants.
5. Participants inspect the publication under **Published offers**. This grants no generic private-record or attachment access. The compact editor can retrieve this bounded menu; server-side compact binding locks the publication and authority through acceptance. Existing disabled Exchange/result prerequisites remain in place.
6. The originating state can withdraw a submitted, reviewed or published offer, and withdraw a submitted/verified authority. An expired or withdrawn authority prevents new offer review/publication. Safe abandonment remains possible after authority expiry. No editing or replacement mutates an existing published snapshot; start a new bound packet/offer for changed terms.

State and offer packets created before migration 018 remain readable historical preparations. They lack the server-recorded origin and immutable binding, so the new write/review actions do not silently migrate or infer authority for them. Create a fresh bound packet to continue preparation. Existing explicitly synthetic downstream fixtures retain their earlier published-only compact path; that fallback does not authorize a newly bound withdrawn offer.

## Persistence, recovery and existing obligations

Migration `018-synthetic-state-offers.sql` adds immutable origin, canonical rate, verified authority and disclosed publication tables. Runtime callers have no direct table access. Narrow security-definer functions re-read current database roles and scope, and only the catalogue projection crosses the private-record boundary. No production authority table is written and no generic record-read policy is broadened.

Verification/publication run in the same transaction as the encrypted case revision, receipt, audit entry and outbox event. A routing, rate or binding rejection rolls everything back. Concurrent exact retries recover one original version/receipt. Recovery still requires current private-record access; withdrawing later does not replace the original publication result with the current withdrawn version.

New compact choices require the current unwithdrawn publication and exact active authority under shared locks. An already effective compact instead validates its frozen majority approval, compact/association/match/offer identities, approved revision and digest, complete original offer publication where present, and copied financial terms. Annual calculation and independent calculation review then retain those fixed terms after future offer withdrawal. A malformed or mismatched approval is rejected; an unbound legacy fixture still requires a currently published accessible offer. This does not execute a payment or a compact.
